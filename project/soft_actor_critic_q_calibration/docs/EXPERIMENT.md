# Running and inspecting the first action-probing experiment

This implementation follows [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md). It is a new experiment; the previously deleted waypoint-calibration implementation has not been restored. The user's [brainstorm](../BRAINSTORM.md) and [actor-gradient notes](../learnings/actor_gradient_breakdown.md) remain separate from implementation documentation.

## Setup

Both frozen snapshots are the completed 4-billion-agent-step learner checkpoints in `project/sac_gpu_4b_comparison`: TES epoch 2422 and PQL epoch 2127. Use full `trainer_state.pt`, not actor-only `final_model.pt` or misleadingly named actor-only best-state files. The loader strictly restores the matching actor, twin online/target critics, and alpha; it allocates no replay or optimizer.

Reference generation uses CARLA self-play with saved training timestep, rewards, randomization, goals, scene density, and termination behavior. Training-mode flags remain enabled; benchmark evaluation mode is not used. Partner-blindness and phantom-braking probabilities and triggers are explicitly set to zero so every active agent follows the policy. This is a documented distribution change from training, not exact reproduction of training's scripted perturbations.

For short episodes, probe selection adapts to the observed span with at least two eligible agents. Three distinct frames near 10%, 30%, and 50% of that span are selected, with two reproducibly sampled eligible agents per frame. Missing eligibility is reported. No collection crosses a scene reset.

The first experiment uses two scene initializations, up to twelve probe situations, twelve actions, and eight continuation seeds per model (up to 1,152 branches). The same continuation seed is paired across alternative first actions. It seeds policy sampling, not a replacement world state. Subsequent actions depend on the branch's actual observations; other agents do not replay the reference future.

## Validation and launch

Activate the repository environment before commands:

```bash
source .venv/bin/activate
python -m pytest -q project/soft_actor_critic_q_calibration/development/tests
python -m project.soft_actor_critic_q_calibration.development.launch_first \
  --output project/soft_actor_critic_q_calibration/runs/first_example --dry-run
```

After native parity, deterministic reconstruction, the 24-branch execution gates, and review pass, omit `--dry-run` to start the experiment in two durable tmux sessions. The launcher defaults to GPU 6 for TES and GPU 7 for PQL; `development/configs/first_experiment.json` records the scale and checkpoint paths. Use a new output directory. The launcher does not start training or change checkpoints.

For an individual execution gate, use the collector with one episode, one probe and two repetitions. `--reference-cap` is an optional instrumentation-only cap, not a full-horizon calibration setting:

```bash
CUDA_VISIBLE_DEVICES=6 OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 \
python -m project.soft_actor_critic_q_calibration.development.run_probes \
  --checkpoint project/sac_gpu_4b_comparison/runs/tes_gpu_4b_20261110/trial_98/learner/trainer_state.pt \
  --output project/soft_actor_critic_q_calibration/runs/gate_example/tes \
  --device cuda:0 --episodes 1 --max-probes 1 --repeats 2 --branch-batch-size 24 \
  --seed 20261114 --cpu-threads 2
```

The collector writes a manifest, progress, reference action prefixes and probe data incrementally. Re-running its exact command can resume completed probes only when the recorded immutable inputs match. A branch batch uses one vectorized native step and batched actor inference. Reconstructing prefixes uses recorded joint actions, avoiding redundant network inference during prefix replay.

## Reading results

Data, manifests, logs, references, probes, and run summaries remain under `runs/<run>/<model>/records/`. Generated images live under `runs/<run>/<model>/plots/`, with at most one README per plot folder. Derived tables, JSON counts, and extra notes live under `runs/<run>/<model>/records/analysis/`. Start with [PLOTS.md](PLOTS.md) to find figures. All plotting scripts use this layout automatically while accepting the original run directory as input.

The requested eight entries are reward return, standard soft return, Q1, Q2, min-Q, reconstructed training-formulation target, safety/ending flags, and goals reached. Metadata includes forced action, continuation seed, starting situation, horizon, missing-tail discount, and validity/ending information.

```bash
python -m project.soft_actor_critic_q_calibration.development.summarize_probes \
  project/soft_actor_critic_q_calibration/runs/first_example/tes
```

`action_summary.csv` contains action means and standard errors within each probe. Paired action differences are not generated by default. If a specific comparison becomes useful, `--include-paired-differences` optionally produces differences against action 0 using matched continuation seeds. Existing paired-difference files from earlier runs are not removed automatically. Safety means are empirical event frequencies; goals also determine whether any goal was reached.

The reconstructed target is the label the current checkpoint-specific update formula would produce from these new continuations, not a historical replay target. SAC uses one-step soft bootstrap; PQL uses the existing raw-reward lambda recurrence with its checkpoint horizon and endpoint-soft convention. Neither is independent ground truth.

Standard soft return excludes initial-action entropy and includes subsequent sampled-action entropy. It stays separate from the implemented PQL target. A timeout/cap/validity gap is censored: the observed suffix sum is not a complete-return reference. The optional target-derived tail is labeled separately and does not remove that limitation.

Repeated futures condition on a particular full simulator state; the critic sees its packed observation, which may omit relevant state. Results from different agents and frames in one scene are correlated. Two scene initializations and eight repetitions per action are a first diagnostic, not a population-level claim or reliable estimate of rare-event probabilities. TES and PQL generate their own on-policy reference situations; their rows are not automatically paired across models.

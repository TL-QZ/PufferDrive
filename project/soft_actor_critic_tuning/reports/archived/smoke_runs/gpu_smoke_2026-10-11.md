# Two-GPU SAC launch validation — 2026-10-11

Archived smoke validation. Settings and paths describe the historical check.

**Passed:** the new launcher ran the real Drive SAC learner on two NVIDIA RTX
A6000 GPUs, performed updates, saved checkpoints, and shut down normally.
W&B, Neptune, TensorBoard, and remote model uploads were disabled throughout.
The full 16-trial experiment was not launched.

## Command

From the repository root:

```bash
bash project/soft_actor_critic_tuning/scripts/launch_sweep.sh \
  --smoke --gpu-pairs '0,1' --max-concurrent 1 \
  --output-dir project/soft_actor_critic_tuning/runs/gpu_smoke_verified_20261011
```

The child processes also received `WANDB_MODE=disabled`. The smoke used actual
Drive simulation, the full DriveSAC architecture, twin critics and targets,
two-rank NCCL/DDP, BF16 autocast, and CPU replay. No simulator or learner source
changes were needed.

All logged learner losses were finite. The saved learner checkpoint was loaded
on CPU and its counters matched the summary: epoch 5, 15 learner updates, and
390,400 agent rows. It contains online and target critics, actor, optimizer,
temperature, scheduler, RNG, and counter state. Replay/environment continuation
is not included. After exit, `nvidia-smi` showed no active CUDA processes.

The CUDA allocator numbers come from PyTorch rank records; device memory and
utilization come from one-second `nvidia-smi` samples and include CUDA overhead.
The samples include idle time before and after the trial. Peak utilization is
not an average throughput measurement.

## Other checks and limits

The production dry run generated all 16 distinct combinations with three-hour
targets, unique run/output paths, 8,192,000 replay entries per rank, and the
requested `pufferdrive_vanilla_sac_tuning` project. Python and shell syntax checks
passed. Offline checks covered configuration merging, invalid launcher inputs,
refusal to overwrite existing output, queue concurrency, timeouts, required
artifacts, nonfinite losses, and process cleanup.

The real smoke deliberately reduced replay and environment counts. It verifies
the production model and minibatch execution, not full-replay initialization,
long-run learning quality, benchmark results, full-cycle shutdown latency, or
W&B authentication/uploads. The full replay RAM estimate for two simultaneous
trials is about 248.4 GiB including 10% headroom; available host RAM is checked
again at launch. Four simultaneous trials would need about 496.8 GiB and exceed
the available RAM observed during this check.

An initial temporary preflight exposed `vec.sync_traj` as an unsupported
`vector.make` argument. The experiment config now uses Multiprocessing's default
ordered receives instead of passing that option. A smaller prototype then
completed 24 updates on both GPUs before this launcher smoke. Review also found
that crashed ranks could leave vector workers behind. After the GPU smoke, the
launcher was updated to track owned descendants and clean survivors before
reusing a GPU pair; a synthetic parent/rank/worker crash check verified that fix.
Tracking polls every 250 ms, so cleanup is best effort rather than strict process
containment.
